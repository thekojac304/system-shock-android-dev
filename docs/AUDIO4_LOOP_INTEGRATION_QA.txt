The generated compact manifest is AUDIO4_SELECTED_LOOPS.tsv (tab-delimited,
versioned comment plus header). The C runtime table Audio4Loops.h is generated
from the same validated selection. A runtime track opens only when its exact
file SHA-256 matches that row. Mismatch or absent metadata uses legacy whole-file
playback and logs a warning. Hashing occurs once when the track opens, not per
frame. User-owned files remain outside the APK. The table is keyed by pack
track ID and can later be extended for Windows, SS2 and custom packs.

Times are decoded PCM frames at sample_rate. Intervals are half-open. The
listed loop_end_sample for faded auditions is extended by the overlap length;
loop duration is (hard_loop_end_sample-loop_start_sample)/sample_rate. For a
faded audition, AUDIO4 analysis blended [hard_end, loop_end) against the
corresponding head [start, start+fade) and continued at start+fade. SDL_mixer
currently has one music stream and cannot produce that true two-source blend.
Runtime seeks at hard_loop_end to loop_start for all selections, preserving the
musical period and avoiding the outro. Four faded selections are approximate
hard joins; sequential fade out/in is not claimed as equivalent. Audible splice
quality, clicks and stalls require hardware listening. Mix_GetMusicPosition is
a decoded cursor and may lead audible output by a buffer; boundary accuracy is
best effort, not sample exact. True overlap requires a future multi-stream backend.

Runtime and resume
First playback starts at 0 and keeps the intro. Region tracks use SDL_mixer
with zero whole-file repeats, polling the decoded cursor from the main/game
thread and seeking to the approved start at the hard end. A failed boundary
seek logs an error and returns to whole-file playback. Unmatched or stale
files retain the existing whole-file mode. Explore and Combat retain separate
runtime positions and the existing 1000 ms sequential transitions, stock
combat threat/hold, legacy Explore filenames, and missing-track fallbacks.
An intro position resumes exactly. An out-of-range body position is reduced by
the hard-loop period into [start, hard_end). The old within-five-seconds-of-end
restart guard applies only when no valid loop metadata is loaded. Deck and
load resets clear positions; no position or break timer enters save data.

Exploration Music Breaks
Preference: exploration_music_breaks = false (default). This is a prefs.txt
setting; the legacy in-game options screen was not expanded. On the QA app,
set the key to true after stopping the game, or run
python scripts/install-qa-soundtrack.py --exploration-music-breaks on
after stopping the QA app. Only owned external Explore playback accrues eligible
game time.
The music-on interval is independently randomized between 360 and 600 seconds;
the silent interval between 60 and 150 seconds. A separate xorshift audio RNG
is seeded from SDL ticks and never touches gameplay RNG. Both outgoing and
incoming intentional-rest fades last 2000 ms. The rest silences only the music
stream; SFX, ambience, machinery, enemy sounds and audiologs retain their
existing paths. A naturally completed rest restarts Explore at 0 for a fresh
intro. Combat interrupts rest immediately, starts Combat with the existing
1000 ms entrance, and resets the next rest schedule. After Combat, Explore
returns; the interrupted rest does not resume. Menu/theme suspension,
backgrounding and non-gameplay updates do not consume either timer. New game,
load and deck changes reset the rest state and schedule. Missing external
Explore never enters an artificial rest over stock music. The feature remains
OFF until hardware listening confirms it is useful.

QA-only accelerated build option: -Prp5npAudio4FastBreaks=true on assembleQa
or scripts/build.ps1 -Variant qa -Audio4FastBreaks
uses 30–45 seconds on and 15–25 seconds rest. Normal QA and production builds
use the full ranges. This option changes no saved preferences and is not a
runtime slider. Tests inject exact tick targets instead of waiting minutes.
