SOURCE FINDINGS / DESIGN
1. newai.c:do_stealth_stuff -> ai_spot_player calls ai.c:ai_critter_seen for a nonfriendly,
   awake critter after successful visibility detection. run_combat_ai calls
   musicai.c:mai_attack on entering an attack posture. Both refresh
   mlimbs_combat to game_time + 1000. CIT_CYCLE is 280 ticks/second: about
   3.57 game seconds, affected by pause/reflex game-time scaling. Player gunfire
   alone does not set this timer; environmental damage feeds danger layers.
2. musicai.c:mlimbs_do_ai expires that timer. Damage above 40 or HP below 10
   selects danger layers; damage decays by 6 every >300 game ticks. The Bridge
   peril-zone exception clears combat and sets minimum peril. Preserve it.
3. gamesys.c:check_nearby_objects refreshes peril about once a game second.
   Awake nonfriendly critters within distance <4 set it, without a visibility
   requirement. physics.c also sets in_peril from map tiles. Startup sets high
   peril. This is not a reliable active-combat signal and has no third content
   model here. PERIL remains Explore externally.
4. airupt.c:grind_music_ai chooses Walking, Peril, then Combat only when the
   combat timer is set, actual_score is Peril/Combat and peril_bars >2.
   peril_bars advances on Peril sequencing calls, not elapsed seconds.
   mlimbs_do_ai drives sequencing when track 0 has ended (IsPlaying), despite
   its stale six-second-timer comment. MacTuneQueueTune is a stub; requests
   start via make_request/StartTrack. Transitions and layering are theme-table
   driven. There is no universal fixed stock audible engage/release latency.
5. On disengagement the timer normally expires after ~3.57 seconds; proximity
   or map peril can keep stock at Peril. objsim.c critter destruction calls
   mai_monster_defeated, clearing the GLOBAL combat timer even with other
   enemies alive. mai_monster_nearby(NO_MONSTER) also clears it but has no
   caller in this tree; gamesys directly assigns mlimbs_monster instead.
6. AUDIO2 returns before timer expiry/danger housekeeping and MIDI sequencing.
   Keep only that existing housekeeping block running before the external
   update, while leaving MIDI sequencing suppressed. Drive AUDIO3 from the
   live combat deadline, not stale score enums or proximity. No AI changes.
7. Hysteresis: retain the last observed stock deadline even if another critter's
   death clears it early. This bridges the evidenced global-clear weakness
   without adding another arbitrary cooldown. No additional minimum dwell.
   Engage on a fresh live threat signal. Initial AUDIO3 used 500 ms fade out /
   500 ms fade in; the AUDIO3.1 tuning test uses 1000 ms for each sequential
   fade because the user reported that the handoff was too obvious. Hardware
   result for the longer sequential fade transition: PENDING.
   Release at the retained deadline plus fades. Poll only during normal updates.
8. Pinned SDL_mixer 2.8.1 music.c: FadeOut is asynchronous; PlayMusic/FadeInMusic
   and FreeMusic can WAIT for an outgoing fade. Never call them on the outgoing
   stream until PlayingMusic is false, or explicitly HaltMusic first on teardown.
   No finished callback, sleeping loop, extra thread or device needed. Keep the
   latest requested state while fading; re-engagement retargets that one pending
   transition. Cache at most two MP3 decoder objects per visit, one playing
   slot; open Combat only on first demand, before fading a working Explore.
9. Prefer <deck>_explore.mp3, then legacy <deck>.mp3; optional <deck>_combat.mp3.
   All AUDIO2 mappings/preferences remain, Original default. Missing/invalid
   Explore variants -> stock for that visit. Missing/invalid Combat -> continue
   Explore; latch the failure until departure. Playback failure -> Explore if
   still usable, else stock. Never alternate external and stock per threat.
10. Deck change disposes the old visit and starts destination Explore. Discard
    an inherited combat deadline on that boundary; a refreshed enemy signal
    engages naturally on the destination. musicai_clear resets external threat
    memory on load/new session, including same-deck loads. No save fields.
11. In-game pause continues music with frozen threat time. Android continues
    using existing SDL device suspension; decoder/fade ownership survives.
    Theme/menu suspension retains decoders and pending fade. Resume the paused
    fade before polling it; never start a track over a suspended outgoing fade.
    Process death starts fresh. No new Android lifecycle callbacks or timers.
12. Audiolog still changes curr_vol_lev through UpdateVolumeXMI. Every new
    playback uses current ducked volume. Avoid writing identical mixer volume
    every frame: it overrides SDL's current fade gain. A real volume change is
    applied immediately; the mixer applies its fade envelope next callback.
13. Minimal files: ExternalMusic.c/.h (owner/state/paths), musicai.c (housekeeping
    and input/reset), installer (accept variant names), audio tests, this doc.
    Existing QA tools suffice; concise transition logs instead of a new UI.
14. Risks: long MP3 open/index latency remains synchronous as in AUDIO2;
    two retained decoders add bounded memory. Fades restart a selected track
    from its beginning. No simultaneous stems or seamless OST loop editing.
    Source timing is not audible hardware evidence. Enemy visibility frequency,
    suitable fade lengths, resume behavior and repeated-transition latency
    require listening on device. Maintenance elevator remains intermittent /
    not reproduced on retest, unknown cause; no fix claimed or behavior changed.

IMPLEMENTATION / VALIDATION RESULTS
Implemented the design above. Original is still the default; no preferences,
game save structures, AI, balance, touch, elevator, SFX, speech, Android device
lifecycle or XMI ownership code changed. Existing Xmi.c hooks are reused.
Two cached decoder handles share ONE SDL_mixer music slot. A re-engagement
during return fade finishes that fade and restarts Combat with a fade-in;
it does not briefly start Explore or reopen the file. Deck changes halt/free
both handles. Unsupported Combat, failed start or unexpected Combat stop is
latched and uses Explore; Explore failure restores stock for that visit.

INSTALL / FILES
Save your session and stop QA before installing owned tracks. Use the existing
helper, which now accepts all three suffixes for each of the eleven deck names:
  python scripts/install-qa-soundtrack.py "C:\MyMusic\Remake" --soundtrack remake
It retains its binary-safe transfer, running-app refusal and backup behavior.
Use files/music/remake/<deck>_explore.mp3 and optional <deck>_combat.mp3;
<deck>.mp3 remains a legacy Explore fallback. Names are lowercase on Android.
Deck names: medical, research, reactor, maintenance, storage, flightdeck,
executive, groves, engineering, security, bridge. All three Groves share groves.
Missing/corrupt preferred Explore is tried once, then legacy. Missing both
means stock music. A Combat-only installation still falls back to stock.
After fixing a failed file, leave/revisit that deck or restart the app.
Install QA using adb install -r; do not uninstall or clear app data.
